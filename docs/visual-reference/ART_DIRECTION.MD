# Flyweight — Art Direction

## Core idea

Flyweight should look like a real-time computational neuroscience experiment
that happens to involve fighting.

It must NOT look like:
- a SaaS dashboard
- a generic AI website
- cyberpunk
- an esports template
- a student debug environment
- a collection of Three.js primitives

The experiment itself is the visual identity.

## Desired first impression

Within two seconds, a visitor should visually understand:

A real-looking fruit fly is operating a controller.
That controller corresponds to one fighter.
The fighter is already fighting another opponent.
A live connectome visualization reacts beside the fight.

The desired reaction is:

"Wait — the fly is controlling that fighter?"

## Public structure

Keep:

WATCH
FIGHT
SCIENCE

Do not expand public navigation.

WATCH is the default experience.
FIGHT lets the user challenge the current Fly champion.
SCIENCE explains what is actually happening.

## Visual language

Primary palette:

Black / graphite / dark neutral environment
Warm amber / oxide = Fly-controlled fighter and activity
Steel / slate blue = opponent / human
Ivory / warm white = typography and neutral UI

Avoid neon.
Avoid purple/green AI gradients.
Avoid decorative gradients generally.

Use real 3D lighting and materials instead.

## Fly

The Fly is the visual protagonist.

It should look biologically recognizable:
- Drosophila proportions
- red compound eyes
- tan/golden body
- six legs
- translucent wings
- readable thorax and abdomen

Do not make it cartoon-cute.
Do not exaggerate the eyes.
Do not turn it into a mascot blob.

It should feel like a strange real animal operating a machine.

## Fly operator station

The Fly visibly operates a small controller / input device.

The visual relationship must read:

FLY
→ CONTROLLER
→ AMBER FIGHTER

without explanatory text.

Controller inputs visually correspond to real selected actions.

## Fighters

Fighters are stylized experimental training mannequins.

They should be:
- faceless
- athletic
- clean
- human-proportioned
- rigged
- readable in silhouette
- slightly synthetic/laboratory in character

They should NOT look like:
- Roblox characters
- stick figures
- superheroes
- military characters
- robots covered in detail
- realistic people

Use one common character language.

Fly fighter:
amber / oxide / warm orange.

Opponent:
steel / slate / cool blue-gray.

## Environment

The environment is a Neural Combat Test Chamber.

The current chamber is a useful base, but should be refined.

Visual ingredients:
- matte physical floor
- restrained grid / measurement markings
- test-zone boundaries
- overhead practical lighting
- observation-lab feeling
- grounded contact shadows
- dedicated Fly operator station
- physical wall/material depth

It should feel built, not generated.

Avoid:
- sci-fi spaceship interiors
- glowing neon strips
- giant holograms
- boxing stadium clichés
- empty black voids

## Camera

Fight readability comes first.

Mostly stable side-on fighting-game camera.

The Fly/operator station may occupy a foreground corner or side area,
but must not obscure combat.

Use very small:
- hit impulses
- follow movement
- KO reframing

No constant cinematic movement.

## Lighting

Use:
- strong readable key light
- fill
- rim/separation
- contact shadows

Never hide low-quality assets with darkness.

The Fly's eyes, wings, legs and abdomen must remain readable.

## Connectome

Runtime activity must always come from real controller values.

If real spatial neuron coordinates can be mapped reliably:
use them.

If they cannot:
keep the visualization explicitly labelled CONNECTOME ACTIVITY MAP.

Never fake anatomical activation.

A real anatomical brain shell may be used as context only if its provenance
and relationship to the activity visualization are clear.

## UI

UI is secondary to the experiment.

Prefer:
scene
motion
spacing
typography
composition

over:
cards
badges
boxes
panels
microcopy

WATCH should contain almost no explanatory prose.

SEES → ACTION → RESULT stays.

The event stream stays compact.

Raw checkpoint IDs and technical methodology belong in SCIENCE.

## Quality bar

A screenshot of Flyweight should look appropriate beside:
- a fly playing blackjack
- a fly operating a keyboard
- a fly in a 3D training environment
- a live fly-brain visualization

It should not immediately look like the cheaper/student version.

Every public screenshot should feel intentionally art-directed.
